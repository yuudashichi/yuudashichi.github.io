  4. 创建执行器：执行器管理 -> 新增 -> AppNameone-coupon-merchant-admin，名称牛券后管平台

    执行器是一个运行在目标服务器上的应用程序模块，用于实际执行由调度中心下发的任务。执行器可以看作是任务的“工作节点”，负责接收调度中心发送的任务调度请求并执行具体的任务逻辑

  5. 创建任务：任务管理 -> 新增

    具体的定时任务

    1. 调度类型：
      • BEAN：通过 Spring 管理的 Bean 来执行任务
      • GLUE：通过在 XXL-Job 控制台上直接编写的脚本（如 Groovy、Java 等）来执行任务
    2. JobHandler：通过@XxlJob指定的要定时执行的Bean
    3. 路由策略：执行器可能是多实例，选择哪个实例执行的策略
    4. 调度过期策略：由于网络延迟或执行器问题等造成没有按时执行时的策略
    5. 阻塞处理策略：上一次任务还没执行完，这次又触发了该怎么做的策略

缓存

缓存击穿

在高并发的系统中，一个热点数据缓存过期或者在缓存中不存在，导致大量并发请求直接访问数据库，从而给数据库造成巨大压力，甚至可能引起宕机

解决方案：

  • 缓存预热：针对已知的热点数据从数据库加载到缓存中，避免海量请求第一次访问热点数据需要从数据库读取的流程
  • 永不过期：热点数据永不过期，在活动开始前，设置过期时间为 -1
  • 加锁：第一个没查到缓存的线程获取互斥锁去重建缓存，其他线程等待
  • 逻辑过期：添加逻辑过期字段，第一个发现过期的线程获取互斥锁，新开一个线程去重建缓存，其他线程返回旧数据

通过分布式锁 + 双重检查解决缓存击穿

只有获取到锁的线程去更新缓存；获取到锁后再判断一次缓存是否已重新构建，防止重复查询数据库

缓存穿透

用户每次访问不存在的数据，请求没办法命中缓存，每次都访问数据库

解决方案：

  • 缓存空值：查询数据库结果为空也进行缓存。若短时间有存在大量恶意请求会大量占用内存
  • 布隆过滤器：将所有存量数据全部放入布隆过滤器，然后如果缓存中不存在数据，紧接着判断布隆过滤器是否存在，如果存在访问数据库请求数据，如果不存在直接返回错误响应即可

使用布隆过滤器 + 缓存空值 + 分布式锁解决缓存穿透
